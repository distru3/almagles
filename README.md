# رجال الأمة — موقع عربي متكامل

موقع نشر إسلامي بالكامل بالعربية (RTL): منشورات حسب الفئات، الجدول الأسبوعي، التفاعلات، التعليقات والردود، ولوحة إدارة.

## البنية

| الجزء | التقنية |
|---|---|
| الواجهة | React 18 + Vite 6 + Tailwind CSS 4 + React Router 7 |
| الخادم | Node.js + Express 4 + Prisma 5 |
| قاعدة البيانات | PostgreSQL (Neon) |
| الصور | Cloudinary (اختياري) |
| الاستضافة | Render (خدمة واحدة تخدم الواجهة والواجهة البرمجية) |

## التشغيل محليًا

1. انسخ المتغيرات:
   ```bash
   cp server/.env.example server/.env
   ```
2. املأ `DATABASE_URL` بوصلة Postgres (Neon) في `server/.env`.
3. ثبت الاعتماديات وأنشئ قاعدة البيانات:
   ```bash
   npm install
   npm run db:generate
   npm run db:migrate
   npm run db:seed
   ```
4. شغّل الخوادم:
   ```bash
   npm run dev
   ```
   - الواجهة: http://localhost:5173 (الخادم يتحكم بـ `/api` عبر Vite proxy)
   - الخادم: http://localhost:4000

## البيانات الأولية (Seed)

- `npm run db:seed` — ينشئ الأقسام، وينشئ حساب مشرف **فقط إذا لم يكن في الموقع أي مشرف** (من `SEED_ADMIN_EMAIL` و`SEED_ADMIN_PASSWORD`). آمن على قاعدة البيانات الحية ولا يغيّر أي حساب موجود.
- `npm run db:seed:demo` — يضيف بيانات تجريبية (حسابات `demo@almagles.app` و`writer@almagles.app` بكلمة مرور `SEED_DEMO_PASSWORD`، وأسبوعين من الجدول — دون أي منشورات). **يرفض العمل على أي قاعدة بيانات غير محلية** حتى لا تصل البيانات التجريبية إلى الموقع الحي؛ للتجاوز على قاعدة بعيدة مؤقتة فقط: `ALLOW_REMOTE_DEMO_SEED=1`.

## الأدوار والصلاحيات

- `visitor` — حساب عادي: تصفح، تعليق، وتفاعل فقط، دون أي صلاحيات إدارية.
- `writer` — كاتب: ينشر من صفحة مخصصة (`/write`) في الأقسام الموكلة إليه فقط (إضافة/تعديل/حذف أي منشور ضمنها، وحذف التعليقات على منشوراتها). إذا مُنح صلاحية الجدول يُفتح له أيضًا صفحة مخصصة (`/manage/schedule`). عند منح هذا الدور يجب تحديد قسم واحد على الأقل وتُنظَّم العملية بنافذة تنبيه للمشرف.
- `admin` — مشرف عام: لوحة تحكم كاملة (منشورات، أقسام، جدول، تعليقات، مستخدمون) وإعادة توزيع الصلاحيات فورًا دون إعادة تشغيل.

## الإنتاج (Render)

- استخدم ملف `render.yaml` (Blueprint) أو Dockerfile المرفق.
- المتغيرات المطلوبة: `DATABASE_URL`, `JWT_SECRET`, `NODE_ENV=production`, وباختياري `CLOUDINARY_*`.
- الترحيلات تُشغَّل تلقائيًا بـ `npx prisma migrate deploy --schema=server/prisma/schema.prisma`.
- الخادم يخدم الواجهة المبنية من `client/dist` تلقائيًا عند `NODE_ENV=production`.

## الجدول الأسبوعي (مدموج من almagles-schedule)

إدارة الجدول (للمشرف ومن لديه صلاحية الجدول) تشمل: إضافة الجلسات وتعديلها مباشرة مع حفظ تلقائي، نقل جلسة ليوم آخر، الحذف مع التراجع، نسخ الأسبوع السابق، الأعمدة المخصصة (مثل «الشيخ» و«الكمية»)، اقتراحات أثناء الكتابة، تنزيل PDF بروابط قابلة للنقر، وتصدير/استيراد CSV بنفس صيغة التطبيق القديم.

### استيراد البيانات من تطبيق الجدول القديم (Firebase)

السكربت آمن للتكرار — يطابق الجلسات بمعرّفاتها في Firebase فيُحدّث ولا يكرر. بدون `--apply` لا يكتب شيئاً ويعرض ما سيتغير فقط:

```bash
npm run db:import-schedule                       # تجربة دون كتابة
npm run db:import-schedule -- --apply            # الاستيراد الفعلي
```

- `--replace-overlaps` يحذف جلسات الموقع (غير المستوردة) الموجودة في نفس أيام الاستيراد حتى لا تتكرر.
- `--prune` يحذف جلسات استُوردت سابقاً ثم حُذفت من التطبيق القديم.

يمكن إعادة تشغيله في أي وقت ما دام التطبيق القديم مستخدماً.

## الإشعارات

- **داخل الموقع:** جرس في الأعلى بعدد غير المقروء، وصفحة `/notifications`. يُنبَّه المستخدم عند: تعليق على منشوره، رد على تعليقه، تفاعل مع منشوره أو تعليقه، ونشر منشور جديد.
- **على الهاتف (PWA + Web Push):** من صفحة الإشعارات يضغط المستخدم «تفعيل الإشعارات» فتصله الإشعارات كإشعارات التطبيقات حتى والموقع مغلق.
  - أندرويد/كمبيوتر: يعمل مباشرة من كروم أو إيدج أو فايرفوكس، ويمكن تثبيت الموقع كتطبيق.
  - آيفون (iOS 16.4+): يجب أولاً «إضافة إلى الشاشة الرئيسية» من سفاري ثم فتحه من الأيقونة.
  - يتطلب HTTPS (أو `localhost` للتجربة على الكمبيوتر) ومفتاحي `VAPID_*`؛ بدونهما تبقى إشعارات الموقع فقط.
- **الجدول:**
  - «تحديث الجدول»: عند إضافة جلسة أو تعديلها أو نقلها أو حذفها يصل إشعار لكل الأعضاء (عدا من عدّل). التعديلات المتتالية تُجمع في إشعار واحد يُرسل بعد دقيقتين من آخر تعديل، ولا يُنبَّه على أيام مضت.
  - «حان وقت المجلس»: لكل جلسة زر جرس في محرر الجدول لاختيار «وقت التنبيه» (بتوقيت جهاز المشرف). عند هذا الوقت يصل إشعار للجميع يبقى على الشاشة حتى يُغلق، مع اهتزاز طويل على أندرويد. لا يمكن لتطبيق ويب اختيار نغمة خاصة أو الرنين المستمر كالمنبّه؛ يُسمع صوت الإشعار العادي للهاتف.
  - **مهم على خطة Render المجانية:** الخادم ينام بعد ١٥ دقيقة بلا زيارات فلا تخرج التنبيهات في وقتها. اضبط خدمة مجانية مثل cron-job.org أو UptimeRobot لتطلب `https://<الموقع>/api/health` كل ١٠ دقائق. التنبيه الذي يتأخر أكثر من ٣٠ دقيقة يُلغى.

## المتغيرات البيئية

| المتغير | مطلوب | الوصف |
|---|---|---|
| `DATABASE_URL` | نعم | وصلة Neon Postgres |
| `JWT_SECRET` | نعم | لتوقيع التوكنات |
| `PORT` | لا | الافتراضي 4000 |
| `CLOUDINARY_CLOUD_NAME/API_KEY/API_SECRET` | لا | تفعيل رفع الصور |
| `SEED_ADMIN_EMAIL` / `SEED_ADMIN_PASSWORD` | للبذر فقط | حساب المشرف الأول إن لم يوجد مشرف (لا يحتاجهما الخادم) |
| `SEED_DEMO_PASSWORD` | للبيانات التجريبية فقط | كلمة مرور الحسابات التجريبية في `db:seed:demo` (محلياً فقط) |
| `ACCESS_TTL_MINUTES` | لا | مدة صلاحية رمز الدخول بالدقائق (الافتراضي 15) |
| `BREVO_API_KEY` | نعم في الإنتاج* | إرسال رموز التحقق عبر واجهة Brevo (HTTPS) |
| `EMAIL_FROM` | نعم في الإنتاج | عنوان المرسل الموثّق في Brevo (مثلاً بريدك على Gmail) |
| `EMAIL_FROM_NAME` | لا | اسم المرسل الظاهر — الافتراضي «رجال الأمة» |
| `APP_BASE_URL` | لا | رابط الموقع (لرسائل البريد لاحقًا) |
| `VAPID_PUBLIC_KEY` / `VAPID_PRIVATE_KEY` | لإشعارات الهاتف | مفتاحا Web Push — يُنشآن مرة واحدة بـ `npx web-push generate-vapid-keys` ولا يُغيَّران بعدها |
| `VAPID_SUBJECT` | لا | بريد تتواصل به خدمات الإشعارات عند وجود مشكلة (الافتراضي `mailto:admin@almagles.app`) |

> *`MAIL_DEV_MODE=0` في التطوير يُفعّل الإرسال الفعلي عبر Brevo؛ الافتراضي في التطوير هو طباعة الرموز وإعادتها في الاستجابة (لا في الإنتاج).
